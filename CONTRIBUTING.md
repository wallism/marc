# Contributing

Keep the controller and skill catalogue generic. Place executable modules in src/quality and a skill's instructions/references inside its folder under skills. Read the [layout rationale](docs/repository-layout.md).

Propose a focused change with its intended behavior, evidence and validation. Preserve mandatory assurance gates, independent reviewer sessions, source/base/policy binding, reviewed exception scope, budgets and guarded actions. Community instructions do not inherit credentials or merge authority. Installation and version upgrades are deliberate.

For a bug, add a focused regression that fails for the defect before fixing it. Run affected local Node tests, then the shared suite when appropriate. Do not run hosted workflows, model evaluations or the optional .NET hook build merely to change documentation. State checks that were waived or unavailable. A local pass is not hosted CI or live-controller proof.

Branch pushes run `npm run build` (JavaScript syntax validation, with no emitted bundle) and `npm test`. PRs run `npm run validate:catalogue` and `npm run test:scenarios`; fork PRs also run the complete Node checks. For instruction changes, use `npm run eval:plan -- --base origin/master --head HEAD` after committing the candidate and refreshing the base ref. The command compares committed inputs and generates a manual comparison plan without model calls. Include results or a reasoned maintainer-reviewed waiver in the PR; the initial reminder does not enforce either. See [check coverage and manual eval procedure](docs/contribution-checks.md).

Update affected documentation in the same change. Update the affected member/component IMPROVEMENTS.md and root umbrella only for material process changes, following the [register scope](IMPROVEMENTS.md#register-scope). Routine documentation, infographic, formatting and housekeeping edits need no entry unless they change how the process operates. Preserve third-party copyright and licence notices. Follow the [versioned crew contribution contract](docs/crew.md), including declared read-only permissions, semantic version, applicability cases and affected-caller tests. Do not introduce a new optional reviewer by silently replacing a mandatory gate.
